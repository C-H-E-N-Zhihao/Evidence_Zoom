## 5. Assumptions behind ESTIMATED numbers

- Image tokens ≈ w·h/750 after downscaling to ≤1568 px long side and ≤1.15 MP (`app/costs.py`). Not yet checked against a provider: `eval/billing_probe.py` measures it once a key exists.
- Output 100 tokens per call on both sides (`--out-tokens`; billed sweep ≈ 64–103 per call), text tokens ≈ characters/4. Image tokens from `app/costs.py` (calibrated on billed usage, ≈ px/800, no downscale). The page side caches only the image, not the prompt (the app meter caches both, as billed). **Thinking tokens are ignored.** Opus 5.5 always thinks (billed as output), so multi-call routes are under-estimated relative to one-call baselines.
- List prices from `eval/pricing.py` (Anthropic first-party, 2026-11-03). Cache write 1.25×, read 0.1× input unless the model lists its own cache-read price.
- Questions are asked in dataset order per image (8 per image), which is what the cached baseline amortizes over.
- Synthetic clean renders; real claims are open (see section 1 for the robustness link).
