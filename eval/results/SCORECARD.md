## 5. Assumptions behind ESTIMATED numbers

- Tokens use the same model as the app meter (`app/costs.py`), calibrated on billed usage (`token_calibration.json`): image ≈ w·h/800 with no downscale up to 1700×2200 (larger images unverified); prompt ≈ 247 tokens per API call (Sonnet fit; the Haiku fit has a larger intercept and up to 47 % residual across prompt types). On the cached page, image and prompt are cached and only the question (characters/4) is uncached, as billed.
- Output 100 tokens per call on both sides (`--out-tokens`; billed sweep ≈ 64–103 per call). **Thinking tokens are ignored.** Opus 5.5 always thinks (billed as output), so multi-call routes are under-estimated relative to one-call baselines.
- List prices from `eval/pricing.py` (Anthropic first-party, 2026-11-03). Cache write 1.25×, read 0.1× input unless the model lists its own cache-read price.
- Questions are asked in dataset order per image (8 per image), which is what the cached baseline amortizes over.
- Synthetic clean renders; real claims are open (see section 1 for the robustness link).
